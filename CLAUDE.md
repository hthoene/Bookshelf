# Bookshelf: notes for AI assistants and contributors

A self-hosted e-book library: uploads, metadata extraction, a KOReader progress sync server and
an OPDS catalog. Python/FastAPI backend, server-rendered Jinja2 templates with htmx, SQLite.

## Commands

```bash
pip install -e ".[dev]"                                   # set up (inside a venv)
BOOKSHELF_DATA_DIR=./data-dev python -m bookshelf serve --port 8765 --reload
python scripts/dev_seed.py --url http://localhost:8765    # demo data (demo / demo1234)
pytest                                                    # tests (fast, isolated tmp data dirs)
ruff check . && ruff format .                             # lint + format (CI enforces both)
alembic revision --autogenerate -m "describe change"      # after changing models.py
docker compose up --build                                 # production-like run on :8080
```

## Layout

```
bookshelf/
  main.py            create_app(): wires settings, DB, storage, routers, error handlers
  config.py          Settings dataclass, read from BOOKSHELF_* environment variables
  db.py              engine, Base, utcnow(), run_migrations() (Alembic runs on startup)
  models.py          User, AuthSession, Book, ReadingProgress
  deps.py            FastAPI dependencies + Annotated aliases (DB, CurrentUser, AdminUser, ...)
  storage.py         file layout under the data dir (books/, covers/, tmp/)
  formats.py         supported extensions -> MIME types
  security.py        password hashing (bcrypt over md5), token helpers
  templating.py      Jinja env, filters, globals, render() helper; UI label dicts
  icons.py           inline SVG icon set used via {{ icon("name") }}
  routers/           thin HTTP layer: auth, library, account, admin, kosync, opds
  services/          business logic, no HTTP: library, users, sessions, progress, covers, hashing
  services/metadata/ per-format extractors registered with @register("<ext>")
  migrations/        Alembic env + versions (autogenerated, then reviewed)
  templates/         Jinja2 pages, partials/ (htmx fragments), opds/ (Atom XML)
  static/            app.css (design tokens at the top), app.js, vendored htmx.min.js
tests/               pytest; conftest.py has fixtures and an in-memory EPUB builder
scripts/dev_seed.py  demo data for local development
```

## Conventions

- **Layering.** Routers parse input, call services and render. Services raise `LibraryError`,
  `UserError` and similar errors with user-facing messages; routers turn them into responses.
  Services never import FastAPI.
- **Dependencies.** Use the `Annotated` aliases from `deps.py` in endpoint signatures
  (`db: DB, user: CurrentUser`). Pages that need a login raise `LoginRequired`, which redirects.
- **Users and privacy.** Every query for books must be scoped to the current user. Always look up
  books via `library.get_entry(db, user, id)` or filter on `Book.user_id`.
- **Datetimes.** Stored as naive UTC (`db.utcnow()`). KOReader timestamps are unix seconds (int).
- **Schema changes.** Edit `models.py`, then run `alembic revision --autogenerate`, review the
  generated file in `migrations/versions/`, and commit it. Never edit an existing migration.
- **Frontend.** Server-rendered HTML first. Use htmx attributes for partial updates (see the
  library search form and `partials/library.html`) and keep `app.js` for small enhancements only.
  No build step and no frameworks. Use the CSS tokens in `:root`, and check light and dark mode
  and phone widths. The UI language is English.
- **Forms.** Return status 422 and re-render the page with an `error` when validation fails.
  Use POST, then redirect (303) when the action succeeded.
- **Style.** Python 3.12+, type hints, `from __future__ import annotations`, ruff (line length 100).

## Compatibility contracts (do not break)

- **KOReader sync** (`routers/kosync.py`): paths, the `x-auth-user`/`x-auth-key` headers, status
  codes, error codes (2001–2005) and JSON shapes must match koreader-sync-server. The key is
  `md5(password)`, which is why passwords are stored as `bcrypt(md5(password))`.
- **Document IDs** (`services/hashing.py`): `partial_md5` must match KOReader's `util.partialMD5`.
  The library connects progress to books through `Book.partial_md5` / `Book.filename_md5`.
- **OPDS** (`routers/opds.py`): OPDS 1.2 Atom feeds with HTTP Basic auth. Feeds must stay
  well-formed XML, so test with `ElementTree` when you change templates.

## Common extensions

- **New book format.** Add the extension to `formats.py`. For metadata, create
  `services/metadata/<fmt>.py` with an `@register("<fmt>")` function that returns
  `BookMetadata`, import it in `services/metadata/__init__.py`, and add a test.
- **New page.** Add a router function and a template that extends `base.html`. Pass `user` and
  `nav` to the template. Register new router modules in `main.py`.
- **New setting.** Add a field to `Settings` (with a `BOOKSHELF_` variable in `from_env`), then
  pass it through in `docker-compose.yml` as `${VAR:-default}`, and document it in
  `.env.example` and the README table. Users configure Compose only via `.env`.
